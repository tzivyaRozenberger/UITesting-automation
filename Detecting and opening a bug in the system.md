# Detecting and opening a bug in the system
As part of the process of ensuring quality and improving system stability,
it is required to perform proactive tests
to detect faults and document them in a professional and clear manner.

## Mission Objective:
Examining the system's behavior in various scenarios,
identifying functional or logical failures,
and writing a standard and actionable bug report for the development team.

## Areas of responsibility:
* Performing manual testing on one of the modules/screens in the system
* Identifying deviations from requirements or expected behavior
* Documenting the bug according to organizational standards

## Instructions for implementation:
1. Choose an active feature in the system.
2. Perform functional tests and end-of-life scenarios, including:
    * Incorrect or missing input
    * Abnormal sequence of actions
    * Repeated or intensive use of system actions
3. Ensure that the bug is consistently reproducible.

## Requirements for reporting the bug:
The bug will be opened in the bug tracking system and will include:
* A concise and clear title
* A general description of the problem
* Environment (version, browser, operating system)
* Exact Steps to Reproduce
* Expected Result
* Actual Result
* Severity / Priority

### Attached files:
    screenshots, logs, relevant data

## Success criteria:
* The bug is clear and unambiguous
* Can be passed on to the developer without further clarification
* Reflects a real problem or gap in requirements
